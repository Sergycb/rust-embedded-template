- Задачи embassy не могут быть generic: объект, уезжающий в
  `#[embassy_executor::task]`, обязан иметь псевдоним типа (рычагу платы — в
  `bsp`; адаптеру — в модуле `app`, который выбирает его тип{% if protocol_link == "true" %} (`crate::link` —
  `docs/modules/app.md`, «Канал протокола: `crate::link`»){% endif %}, или конкретный тип прямо во
  входе узла) — `docs/architecture.md`.
- Ровно один `#[panic_handler]` и один `#[global_logger]` на бинарник, развилка
  по профилю — `#[cfg(debug_assertions)]`, не Cargo-фича — `docs/diagnostics.md`,
  «Два паникёра, один на сборку».
- `Board` (один, `Board::new() -> Board`{% if has_usb == "true" or has_net == "true" %}, пары из одного конструктора собирает
  плата{% endif %}) отдаёт рычаги платы под трейтами и данные о чипе
  (`bsp::ChipSpec`), а не `Peripherals`, не пины, не периферию ядра и не
  `Clocks` — `docs/architecture.md`, «`Board` отдаёт рычаги платы, а не
  периферию и не протоколы».
- Реализация поверх стандартных трейтов — `adapters`, нужен чип — `bsp`; кто
  строит адаптер, тот держит его память; адаптеры, чей тип или память выбирает
  приложение, строит `app` и отдаёт узлу готовыми — `docs/architecture.md`,
  «Адаптеры делятся по одному признаку — нужен ли чип».
- `bsp` ничего не инициализирует сверх подъёма HAL: конструкторы зовутся `new`
  и только создают объекты. Всё, что запускает железо{% if graph == "true" %} (`arm()` у сторожа){% endif %},
  делает тот, кто этим железом распоряжается. Исключения — `ensure_*` для
  option bytes, `bsp::cache::enable()` (кэши чипа) и `Cycles::new` (счётчик
  тактов) —
  `docs/clocks.md`{% if external_flash == "true" %}; и `init` внешней флеши в `bsp::external::new` (опознание
  микросхемы — без него драйвер не годится ни для одной операции), из-за него
  `Board::new` асинхронный и зовётся из `main` через `block_on` —
  `docs/modules/bsp-external.md`{% endif %}.
- `lib.rs` только объявляет — `docs/conventions.md`, «`lib.rs` только объявляет
  модули».
- `app` про `embassy-stm32` не знает — ни `use`, ни строки в манифесте. Ядро
  `app` берёт напрямую (`cortex-m-rt` — точка входа и `HardFault`, `cortex-m` —
  свободные функции ядра), без обёрток в `bsp`; паника и фолт — в `app`
  (`docs/clocks.md`, «Ядро: фолты, ловушка деления, счётчик тактов»). Сброс МК —
  рычаг `bsp::reset::Reboot`.
- `bsp` не зависит от `domain`: входы узлов из полей `Board` заполняет `app`.{% if ota == "true" %}
  `boot` зовёт из `domain` только `domain::ota::boot::screen_update`.{% endif %}
  Подробности — `docs/architecture.md`.
- Логирование только `defmt`; `log` в прошивке не используется.
- **Если вы в репозитории самого шаблона** (признак — каталог `chip-data-gen/`
  в корне): файлы здесь содержат Liquid и до генерации не являются валидным
  Rust, правки проверяются генерацией (`template-check`, уровень —
  `MAINTAINING.md`, «Какой уровень когда»), а не `cargo build`.
  В остальных случаях (сгенерированный проект) это обычный Rust — собирайте и
  проверяйте как любой другой код.
