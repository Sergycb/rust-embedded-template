Правила целиком — `AGENTS.md`, «Граница `domain`/`cross`»; здесь — что
проверить при правке `domain`.

- Ни `embassy-stm32`, ни знания о железе: всё, что их требует, — в
  `crates-cross`; `supervisor` можно и нужно — `docs/architecture.md`, «Цена
  решения «узлы — в `domain`»».
- Асинхронный код и стейтчарты — логика, место им здесь, даже если результат
  нужен только `cross` — `AGENTS.md`, «Граница `domain`/`cross`».
- Узел — самодостаточный `supervisor_fragment!`; новое слово DSL — фича в
  `crates-host/domain/Cargo.toml` — `docs/architecture.md`, «Узлы — фрагменты в
  `domain`».
- Задача узла — автомат `#[fsm::typestate]`, `match ctx.run().await {}` —
  `docs/architecture.md`, «Каждая задача узла — автомат `#[fsm::typestate]`».
- Узлы не падают — `docs/architecture.md`, «Узлы не падают».
- Адаптер, чей тип или память выбирает приложение, узел получает готовым во
  входе (`LINK: local L = inputs.link`); трейта сборки у таких адаптеров нет —
  `docs/architecture.md`, «Адаптеры делятся по одному признаку — нужен ли чип».
- Трейтов здесь нет — только в `ports` и только под несколько реализаций;
  одна реализация — конкретный тип здесь же, если он не про железо —
  `docs/architecture.md`, «Трейт — только под несколько реализаций».
- Нужное только логике (команды узлам, ошибки её операций) — здесь, подмодулем
  рядом с узлом, а не в `ports`; логика вне автоматов — функции, её состояние —
  локальные переменные вызова — `docs/architecture.md`, «Логика — функции над
  портами и конкретными типами; трейты — только в `ports`».
- (Только в репозитории шаблона.) Liquid — только внутри комментариев и
  строковых литералов — `AGENTS.md`, «Инварианты, которые не ловит компилятор».
