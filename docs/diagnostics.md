# Диагностика падений: паникёр по профилю и регион `PANIC`

## Два паникёра, один на сборку

Выбирает профиль — `#[cfg(debug_assertions)]` в `crates-cross/app/src/panic.rs` и
его копии `crates-cross/boot/src/panic.rs`:

| Профиль | Паникёр | Что делает | Почему |
|---|---|---|---|
| debug | `panic-probe` (`print-defmt`) | печатает причину через defmt, `udf()` | пробник ловит остановку там, где упало, со стеком |
| release | свой `#[panic_handler]` поверх `panic-persist` | пишет причину в регион `PANIC`, печатает её в defmt, `SCB::sys_reset()` | устройство возвращается в работу; причину печатает и следующий старт |

Release-обработчик свой, а не штатный из `panic-persist`, ради строки в RTT: с
подключённым пробником причина видна сразу, без `cargo xtask panic`. Крейт собран с
фичей `custom-panic-handler` — собственного `#[panic_handler]` у него нет, остаётся
`report_panic_info`. Порядок внутри — сначала дамп, потом печать: после
`probe-rs attach` RTT блокирует запись при полном канале, и без пробника печать
встала бы навсегда. Флаг повторного входа не даёт панике внутри самого defmt
затереть первую причину и уйти в рекурсию до конца стека.

`panic-probe` выбирается `use … as _;` под `cfg`: крейт, на который в исходнике нет ни
одной ссылки, не линкуется и своего `#[panic_handler]` не регистрирует. Инвариант —
ровно один обработчик на сборку; нарушение компилятор ловит ошибкой «duplicate lang
item» (или «`#[panic_handler]` function required» — если не остался ни один).

## Регион `PANIC`

Отрезан от конца RAM при генерации (`chip-data-gen`, `PANIC_FRACTION`/`PANIC_MIN`/
`PANIC_MAX`), адресуется
символами `_panic_dump_start`/`_panic_dump_end` из `memory.x` — без секции: секция с
VMA у верхней границы RAM убеждает `flip-link`, что двигать стек некуда, и прошивка
уходит в HardFault на первом же `push`. Формат записи — `panic-persist`: магия
`0x0FACADE0` по смещению 0, длина по 4, байты сообщения с 8; его же читает
`cargo xtask panic` через `probe-rs read`.

Читается сообщение ровно один раз: `get_panic_message_utf8` стирает магию, чтобы одно
падение не всплывало после каждого сброса. Следствие для `cargo xtask panic`: если
release-приложение успело стартовать, дамп уже вычитан и ушёл в defmt-лог того запуска.

## Чего здесь нет

- **`HardFault` не перехватывается.** Разыменование мусорного указателя, невыровненный
  доступ, прыжок по битому адресу приходят вектором `HardFault`, а `cortex-m-rt`
  подставляет туда бесконечный цикл. Под пробником `probe-rs run` ловит отказ vector
  catch'ем и показывает место; в поле плату перезагрузит IWDG (проект с графом задач).
  Записи в `PANIC` при этом нет — только паника доходит до паникёра.
- **Замера стека нет.** От переполнения защищает `flip-link` (HardFault вместо тихой
  порчи статики); «сколько запаса осталось» шаблон не меряет.
