# Документация проекта

«Почему так решено» — здесь. «Что делать» — в `AGENTS.md` (команды, запреты,
чек-лист). Как устроен проект для человека — в `README.md` в корне.

| Файл | О чём | Когда открывать |
|---|---|---|
| `architecture.md` | границы `domain`/`cross`, что пересекает границу `bsp` → `app`, `chip-info` | добавляете код и не знаете, в какой крейт |
| `clocks.md` | дамп частот, `EXPECTED_SYS_HZ`, пороги вроде `IMAGE_BUDGET_PERCENT` | трогаете тактирование или порог проверки |
| `ota.md` | приём образа, подпись, защита от отката, тест полного цикла | трогаете `bsp::ota` или `domain::download` |
| `flash.md` | стёртое состояние (`0xFF` против `0x00`), раздел настроек, один `Flash` на всех | трогаете `bsp::config` или раскладку памяти |
| `watchdog.md` | три связанных таймаута, почему узел `observe`, почему взводится не в `init` | трогаете сторож или тайминги графа задач |
| `diagnostics.md` | замер стека, дамп `HardFault`, формат записи в регион `PANIC` | трогаете `bsp::stack`, `bsp::fault` или паникёр |
| `conventions.md` | feature-флаги, правила добавления зависимостей, осознанные ограничения | добавляете зависимость или фичу |

`modules/` — документация модулей, подключённая в код через
`#![doc = include_str!(...)]`. Правится вместе с кодом модуля, а не отдельно.
