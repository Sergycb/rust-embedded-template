# MQTT-клиент как сетевая служба — дизайн

Дата: 2026-10-22. Статус: утверждён пользователем; проверен builder-check.

## Зачем

У шаблона есть сетевые службы, к которым подключаются снаружи (`rest`, `ssh`),
и протоколы транспортов (Modbus TCP, protobuf). Не хватает самой
распространённой схемы для сетевых устройств: плата **сама** подключается к
брокеру MQTT, публикует о себе данные и принимает команды подпиской. Так
плата видна из-за NAT, а все устройства собираются у одного брокера
(Mosquitto, Home Assistant, Node-RED, Grafana читают его без адаптеров).

Это отправная точка, как `domain::http`: узел с минимальным набором тем, а
свои данные и команды проект добавляет по образцу.

## Цели

- Новая служба `mqtt` в меню `net_services` (рядом с `ssh`, `rest`), только
  при Ethernet-транспорте; `--define net_services=mqtt` — строго, как прочие.
- Узел графа `MQTT` (`domain::mqtt`, фрагмент `MQTT_FRAG`) и задача без графа
  (`crates-cross/app/src/tasks/mqtt.rs`).
- Клиент — `minimq` 0.13 (решение пользователя; зависимость разрешена).
- Брокер вшивается при сборке из файла в корне проекта; адрес узел берёт через
  шов `Broker`, чтобы позже добавить смену на работающей плате без переделки
  узла.
- Набор тем (ниже), переподключение без падения узла, тесты на host.

## Не цели (сейчас)

- TLS (порт 8883, облачные брокеры). Место брокера не выбрано; `minimq` берёт
  любой поток `embedded-io-async`, так что TLS ложится позже обёрткой сокета.
- DNS: адрес брокера — IPv4. Фича `dns` у `embassy-net` занимает сокет и
  отдельная задача.
- Смена брокера на ходу (`Stored`) и общий доступ нескольких узлов к хранилищу
  настроек — отдельная задача; здесь только шов.
- OTA через MQTT, автообнаружение Home Assistant, MQTT 3.1.1 (`minimq` — только
  v5; Mosquitto понимает v5 с 1.6).
- Брокер на плате.

## Анти-цели (провал, даже если «работает»)

- Узел, который при обрыве связи возвращает `TaskExit::Failed` или
  перезапускается графом (нарушает «узлы не падают», AGENTS.md).
- Голый `loop` в задаче узла вместо `#[fsm::typestate]`.
- Пустой пароль/токен там, где это открывает доступ, без явного решения;
  молчаливая подстановка адреса-заглушки, из-за которой плата вечно стучится в
  несуществующий брокер без строки в логе.
- Буферы `minimq` в `bsp` или в `static` вне слота/задачи (буфер — там, где
  создаётся держащий его объект).

## Ограничения проекта (обязательны)

- Граница `domain`/`cross`: вся логика — `domain::mqtt`; `app` только собирает
  вход узла (стек, сведения, брокер, клиент OTA) — AGENTS.md.
- Узел — автомат `#[fsm::typestate]` на контексте фрагмента
  (`ctx: $crate::mqtt::MqttCtx, task: $crate::mqtt::task;`), `restart: Never`,
  `TaskExit::Failed` не возвращает. Отказ связи — лог, пауза, начальное
  состояние.
- Буферы сокета и `minimq` — слоты фрагмента `= static` (как у SSH); в
  задаче без графа — `ConstStaticCell` (как `tasks/http.rs`).
- Liquid в корневом workspace — только в комментариях (`// {%- if … %}`).
- `#![allow(dead_code)]` в `graph.rs` не трогать.
- Новая зависимость для `cross` проверяется холодной сборкой
  (`rm -rf target && cargo build …`) — docs/conventions.md.

## Решения

### Включение (хук `chip-select.rhai`)

- Пункт в `NET_SERVICE_ITEMS`:
  `#{ value: "mqtt", text: "MQTT-клиент (minimq)", needs_rng: false, min_partition: 0 }`.
  RNG не нужен (без TLS криптографии нет).
- `RAM_COST.services.mqtt` — замерить по методике MAINTAINING.md («Оценка RAM»)
  разностью пары сборок, не выводить.
- Удаление `crates-host/domain/src/mqtt.rs` и
  `crates-cross/app/src/tasks/mqtt.rs`, когда `mqtt` не выбран.
  `domain::device` нужен и MQTT (условие удаления `device.rs` — уже
  `services.len() == 0`, менять не надо, проверить).
- `mqtt_ota_client` — номер клиента OTA следом за REST (2 копии) и SSH (1):
  `protocol_clients + (rest ? 2 : 0) + (ssh ? 1 : 0)`.

### Корневой `Cargo.toml` и `domain`

- `minimq = { version = "0.13.5", default-features = false }` под
  `# {%- if net_services contains "mqtt" %}`, с комментарием-обоснованием в стиле
  соседних записей. Фича `defmt` — так же, как у прочих зависимостей решают
  `defmt_or_log` (сверить, как сделано для `picoserve`/`sunset`).
- `heapless` уже приходит при `net_services != ""`.
- `domain/Cargo.toml` — зависимость под тем же условием.

### Конфигурация брокера: файл `mqtt.toml` в корне

```toml
# Брокер MQTT, к которому подключается плата (domain::mqtt).
host = "192.168.1.10"   # IPv4; DNS не поддерживается
port = 1883
user = ""               # пусто — без логина
password = ""
prefix = "devices"      # темы: <prefix>/<uid>/...
```

- Создаёт `cargo xtask` (`secrets::ensure`, вызывается в `build`, `lint cross`,
  перед прошивкой) **заготовкой** выше, если файла нет, и печатает «впишите
  адрес брокера, закоммитьте файл». Существующий не трогает.
- Коммитится (как `rest-token.txt`): пароль всё равно лежит в образе открыто.
- Читает `crates-cross/app/build.rs` **без новой build-зависимости**: разбор
  подмножества — строки `ключ = значение`, `#`-комментарии, строки в кавычках,
  `port` — число. Проверяет: `host` парсится как `Ipv4Addr`, `port` в `1..=65535`,
  `prefix` непуст и без `+`, `#`, `/` на краях; ошибка — `panic!` с понятным
  текстом (сборка падает, а не плата молчит). Отдаёт значения
  `cargo::rustc-env=MQTT_HOST=…` и т. д., `rerun-if-changed` на файл.
- `crates-cross/app/src/net.rs`: `pub const MQTT_BROKER: domain::mqtt::Endpoint`
  из `env!(…)` (IP — разбор в `const` или четыре октета отдельными env —
  на усмотрение исполнителя), рядом `MQTT_USER`, `MQTT_PASSWORD`, `MQTT_PREFIX`.

### Шов `Broker`

По образцу `domain::ssh::HostKey` (`Fixed` / `Stored<S>`):

```rust
pub trait Broker {
    /// Куда и с какими учётными данными подключаться на этой попытке.
    async fn endpoint(&mut self) -> Endpoint;
}
pub struct Fixed(pub Endpoint);   // сейчас: вшитое из mqtt.toml
```

`Endpoint` — адрес (`IpEndpoint` `embassy-net` или `[u8;4]` + порт),
`user: &'static str`, `password: &'static str`. Узел зовёт `endpoint()` в
начале **каждой** попытки подключения — тогда будущий `Stored<S>` применит
новый адрес на следующей попытке. Фрагмент параметризован типом:
`MQTT_FRAG<B>` (как `SSH_FRAG<K>`), граф подставляет `::domain::mqtt::Fixed`.

`minimq` фиксирует логин, пароль, Will и `client_id` в `Session::new`
(`ConfigBuilder::auth`), а `Session::connect` берёт только поток. Поэтому
**`Session` создаётся заново на каждой попытке** (над теми же буферами-слотами)
— учётные данные из `endpoint()` применяются сразу. Это согласовано с решением
ниже не сохранять сессию на брокере. *(решение автора дизайна после проверки)*

### Темы и данные

`<id>` — UID чипа (`DeviceInfo::uid`), 24 строчных hex-знака.

| Тема | Направление | QoS | retain | Содержимое |
|---|---|---|---|---|
| `<prefix>/<id>/status` | плата → | 1 | да | `online`; `offline` — Last Will при `connect` |
| `<prefix>/<id>/info` | плата → | 1 | да | JSON из `DeviceInfo` — те же поля, что `GET /api/info` (вынести общую сериализацию, если она у REST своя) |
| `<prefix>/<id>/telemetry` | плата → | 0 | нет | JSON `{"uptime_s": N}` раз в `TELEMETRY_INTERVAL` (10 с) |
| `<prefix>/<id>/cmd/reboot` | → плата | 1 | — | только при `ota == "true"`: `OtaCommand::Reboot` своим клиентом OTA, как `POST /api/reboot`; ответ — публикация `<prefix>/<id>/cmd/reboot/result` (`accepted` / причина) до сброса |

Подписка — `<prefix>/<id>/cmd/#`; неизвестная команда — строка в лог. Загрузку
CPU в шаблон не кладём: без графа её публикуют только в лог; в модульной
документации — рецепт «добавить поле в телеметрию» (через подписку графа
`cpu_load_percent_receiver()`).

`client_id` MQTT — `<prefix>-<id>` (уникален на брокере).

### Автомат узла

Состояния (имена — на усмотрение исполнителя, смысл — обязателен):

1. **Idle/Backoff** — пауза перед попыткой (0 на первой; дальше 1 → 2 → 4 … ≤ 30 с,
   сброс после успешного подключения).
2. **Connecting** — `broker.endpoint()`, TCP-сокет к брокеру, `Session::connect`
   с Will. Отказ → лог, Backoff.
3. **Online** — подписка на `cmd/#` (каждый раз: сессия не сохраняется);
   публикация `status` = `online` (каждый раз — брокер уже мог разослать Will
   `offline` с retain) и `info`; цикл:
   `with_timeout(до следующей телеметрии, conn.recv())` → команда или
   публикация телеметрии. `Error::Disconnected` и прочие ошибки → лог (с
   адресом брокера), закрыть сокет, Backoff.

Выходное состояние `exit Down { result: TaskExit }` недостижимо (как у SSH).

**Сессия на брокере не сохраняется** (`session_expiry_interval` = 0, умолчание
`minimq`): `ConnectEvent::Reconnected` не наступает, ветки под него нет.
Команда, отправленная, пока плата не в сети, теряется — для `reboot` это
правильно (не перезагружаться запоздало). In-flight QoS 1 после обрыва не
повторяется, tx-буферу не нужен запас под очередь. *(решение автора дизайна
после проверки)*

`publish` QoS 0 в `minimq` не безопасен при отмене: под `with_timeout`
оборачивается только `recv()`, публикация — вне таймаута.

**Подписка на `cmd/#` — с `RetainHandling::DoNotSend`**, и входящая команда с
флагом retain игнорируется (лог): иначе однажды оставленная с retain
`cmd/reboot` перезагружала бы плату при каждом подключении, по кругу.

### Доступ к командам

Решение пользователя: **доступ ограничивает брокер** (логин и ACL на темы), как
принято в MQTT; токена в теле команды нет. При `ota == "true"` и пустом `user`
в `mqtt.toml` `build.rs` выдаёт `cargo::warning` («cmd/reboot примет любой
клиент брокера»), сборку не роняет. В модульной документации — пример ACL
Mosquitto: плате — запись в `<prefix>/<id>/#` кроме `cmd/`, чтение
`<prefix>/<id>/cmd/#`; управляющему клиенту — запись в `cmd/`.

### Разбиение под тесты

Узел делится на тонкую оболочку и ядро. Оболочка — открыть `TcpSocket` на
`Stack` к `endpoint()`, пауза Backoff. Ядро — всё, что после TCP: `Session`,
`connect`, подписка, публикации, команды — функция (или состояние) над любым
`embedded_io_async::Read + Write`. Тесты на host гоняют ядро против
поддельного брокера-потока; оболочка без тестов на host (как сокетная часть
SSH/REST), проверяется `template-check` и на плате. Нового шва-параметра у
фрагмента нет. *(решение автора дизайна после проверки)*

### Заготовка адреса

`build.rs` заготовку `192.168.1.10` **не отвергает** — иначе свежий проект, CI
и `template-check` не соберутся без правки файла. Вместо этого: `xtask` при
создании печатает «впишите адрес брокера», а узел на каждой неудачной попытке
пишет в лог адрес и «проверьте mqtt.toml». *(решение автора дизайна после
проверки)*

`build.rs` проверяет и длины: `client_id` `minimq` — до 64 символов, тема Will
— до 128, отсюда предел длины `prefix` (вычислить точно).

### Ресурсы

- Сокет: `SOCKETS` в `crate::net` — `+ 1` при `mqtt`; комментарий там же.
- Буферы (константы в `domain::mqtt`): TCP rx/tx, `minimq` rx (наибольшая
  входящая публикация — команды короткие, 512 Б хватит) и tx (in-flight + CONNECT
  с Will — ориентир 1 КиБ). Итог сверить с `RAM_COST`.

### xtask и проверки

- `xtask::project` — `has_net_service("mqtt")` уже работает по строке.
- `xtask::secrets::ensure` — заготовка `mqtt.toml` (функция отдельная от
  `ensure_text`: содержимое не случайное), тест «существующий файл не трогается».
- `chip-data-gen/tests/cascade.rs` — `mqtt` в меню при Ethernet, нет без него,
  строгий `--define`, `mqtt_ota_client` с REST/SSH и без.
- `template-check` — случай `links=tcp, net_services=mqtt` и сочетание
  `rest,ssh,mqtt` (номера клиентов OTA, сокеты), плюс один без графа.
- Тесты `domain::mqtt` на host: поддельный брокер поверх `embedded-io-async`
  (как тестовый транспорт у `minimq`/соседей) — подключение с Will, подписка,
  `reboot` → команда OTA, обрыв → Backoff и повторное подключение, неверная
  команда — без паники.
