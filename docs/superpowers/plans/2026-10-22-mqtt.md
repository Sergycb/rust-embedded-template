# MQTT-клиент (служба `mqtt`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** служба `mqtt` в `net_services`: узел `domain::mqtt` на `minimq` публикует статус, сведения и телеметрию платы брокеру, вшитому из `mqtt.toml`, и принимает `cmd/reboot`.

**Architecture:** узел — автомат `#[fsm::typestate]` с тонкой сокетной оболочкой (Backoff → Connecting → Online) и ядром над любым `minimq::Io` (тестируется на host против поддельного брокера). Адрес — через шов `Broker` (`Fixed` сейчас). Генерация (хук), сборка (`build.rs` разбирает `mqtt.toml`), `xtask` (заготовка файла) и граф — по образцу служб `rest`/`ssh`.

**Tech Stack:** Rust `no_std`, Embassy (`embassy-net` 0.9, `embassy-time` 0.5), `minimq` 0.13.5, `heapless` 0.9, rhai-хук cargo-generate, Liquid.

**Spec:** `docs/superpowers/specs/2026-10-22-mqtt-design.md`

## Global Constraints

- Репозиторий — **шаблон**: в `crates-cross/**` живёт Liquid, `cross` в репозитории не собирается — проверяется `template-check` (MAINTAINING.md; изоляция — память «template-check isolation»: занят каталог → `TEMPLATE_CHECK_DIR=C:\tc-<имя>`).
- Liquid в корневом workspace (`domain`, корневой `Cargo.toml`) — только в комментариях `// {%- if net_services contains "mqtt" %}` / `# {%- … %}`.
- `minimq = { version = "0.13.5", default-features = false }`; фича `defmt` — через фичу `defmt` крейта `domain`, как у соседних зависимостей. Других новых зависимостей нет (в т. ч. build-зависимостей для разбора TOML).
- Узел: `restart: Never`, `TaskExit::Failed` не возвращает; отказ связи — лог, Backoff, начало. Без голого `loop` в задаче узла.
- Буферы — слоты фрагмента `= static`; без графа — `ConstStaticCell` в `tasks/mqtt.rs`.
- Темы: `<prefix>/<uid>/status` (QoS 1, retain, `online`; Will `offline`), `/info` (QoS 1, retain, JSON `DeviceInfo`), `/telemetry` (QoS 0, `{"uptime_s":N}`, раз в 10 с), `/cmd/reboot` → результат в `/cmd/reboot/result`. `uid` — 24 строчных hex; `client_id` — `<prefix>-<uid>`.
- Подписка `<prefix>/<uid>/cmd/#` с `RetainHandling::DoNotSend`; входящая команда с retain — игнор + лог.
- Сессия на брокере не сохраняется (`session_expiry_interval` не задавать); `Session` — новая на каждой попытке.
- `publish` QoS 0 не под `with_timeout` (не cancel-safe); под таймаутом — только `recv()`.
- Backoff: 0 перед первой попыткой, затем 1, 2, 4, 8, 16, 30, 30 … с; сброс после успешного `connect`.
- `prefix`: непуст, не длиннее 39 символов (`client_id` ≤ 64), без `/`, `+`, `#`.
- `mqtt.toml` создаёт `xtask` заготовкой (`host = "192.168.1.10"`, `port = 1883`, `user = ""`, `password = ""`, `prefix = "devices"`), коммитится; `build.rs` заготовку не отвергает. `ota == "true"` и пустой `user` → `cargo::warning`, не ошибка.
- Перед отчётом: `cargo xtask lint`, `cargo xtask test host`, `cargo test --manifest-path chip-data-gen/Cargo.toml`, `template-check --only <новые случаи>` — по одной, `EXIT=0`.

## Review Focus

1. Брокер недоступен / отказал в `CONNECT` (неверный пароль) → узел не падает, лог с адресом и «проверьте mqtt.toml», паузы растут до 30 с — тест `refused_connect_reports_refused` (Task 3) и `backoff_grows_to_cap` (Task 2).
2. Обрыв посреди Online (сокет вернул ошибку/EOF) → `Ended::Lost`, повтор без паники — тест `transport_error_ends_session` (Task 3).
3. Команда `cmd/reboot` с retain (оставлена кем-то на брокере) → не перезагружаемся — тест `retained_reboot_is_ignored` (Task 3).
4. Чужая/неизвестная тема или мусор в payload → лог, сессия продолжается — тест `unknown_command_keeps_session` (Task 3).
5. `mqtt.toml` с битым IP, портом 0, длинным/недопустимым `prefix` → сборка падает с понятным текстом — проверки в `parse_mqtt_toml` и тест `bad_mqtt_toml_is_rejected` (Task 5).

**Files:**
- Modify: `crates-host/domain/src/mqtt.rs`

**Interfaces:**
- Consumes: Task 1 `device::write_info`; Task 2 `Topics`, `Command`, `parse_command`, `write_telemetry`, `TELEMETRY_INTERVAL`, `Endpoint`.
- Produces:
  - `pub const RX_BUFFER: usize = 512; pub const TX_BUFFER: usize = 1024;` (буферы `minimq`; окончательные — по замеру в Task 6).
  - `pub(crate) struct Env<'a> { pub topics: &'a Topics, pub info: &'a DeviceInfo, pub mac: [u8; 6], pub ip: Option<embassy_net::Ipv4Address>, pub rx: &'a mut [u8], pub tx: &'a mut [u8], /* ota */ pub ota: &'a OtaClient }` — поле `ota` под `// {%- if ota == "true" %}`.
  - `pub(crate) enum Ended { Refused, Lost }` — `Refused`: `connect` не прошёл (Backoff продолжает расти), `Lost`: был в сети (Backoff сбрасывается).
  - `pub(crate) async fn serve<IO: minimq::Io>(io: IO, endpoint: &Endpoint, env: &mut Env<'_>) -> Ended`:
    1. `Session::new(ConfigBuilder::new(Buffers::new(rx, tx)).client_id(..)?.auth(user, password)?` (auth — только при непустом `user`)`.will(Will::new(status, b"offline", &[])?.retained().qos(QoS::AtLeastOnce))?)`; ошибка конфигурации — лог + `Ended::Refused`;
    2. `session.connect(io)` — ошибка → лог `mqtt: брокер {addr}:{port} не принял подключение — проверьте mqtt.toml` → `Refused`;
    3. `subscribe(&[TopicFilter::new(cmd_filter).options(SubscriptionOptions::default().retain_behavior(RetainHandling::DoNotSend).maximum_qos(QoS::AtLeastOnce))], &[])`;
    4. публикации `status`=`online` (QoS 1, retain), `info` (QoS 1, retain, `write_info` с `uptime_s` от `Instant::now()`);
    5. цикл: `with_deadline(next_telemetry, conn.recv())`; таймаут → `publish` телеметрии QoS 0 вне таймаута, `next_telemetry += TELEMETRY_INTERVAL`; входящая публикация → retain — `warn!` и пропуск; `parse_command` → `Reboot` — `ota.request(OtaCommand::Reboot)`, публикация в `reboot_result` текста `accepted` (`Ok(Ok(Progress::Rebooting))`) или `refused`; `None` — `info!` с темой; любая ошибка `recv`/`publish` → лог → `Lost`.
  - Без OTA ветки `Reboot` нет: `Command::Reboot` → лог «перезагрузка без OTA недоступна».

  - `Topics` строится в `begin` из `prefix` и `info.uid`.
