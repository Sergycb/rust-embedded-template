Аппаратный сторожевой таймер (IWDG) под трейт
[`watchdog::HardwareWatchdog`].

Недостающее звено между графом задач и железом. Всё остальное уже есть в
`rust-lib` и от чипа не зависит: `watchdog::TaskWatchdog` мультиплексирует
несколько программных сторожей (у каждой задачи свой таймаут) в один
аппаратный, а `supervisor` дёргает его из блока `watchdog:` своего графа.
Реализации под конкретный МК там нет и быть не может — те крейты не знают
про HAL, — поэтому она здесь.

{%- if graph == "true" %}
**Всё это уже собрано.** Объект строит `Board::new` (поле `watchdog`,
ещё не запущенный), блок `watchdog:` графа запускает его сам
(`= board.watchdog.arm()`), а узел `APP` объявляет `watchdog:` и
отмечается через `heartbeat.feed()` — см. `app/src/graph.rs`. Ниже —
только то, что стоит знать, прежде чем это менять.

**Запускается он в прологе `spawn_all`, а не в `Board::new` и не в
`main`** — и это не мелочь: с вызова [`Iwdg::arm`] сторож тикает, а
кормить его начинает только тикер графа, так что промежуток между этими
двумя моментами надо держать коротким. Запускай его `Board::new` — тот же
конструктор в target-тестах сбрасывал бы плату посреди теста, где графа
нет вовсе; стой вызов в `main`, туда же попадала бы вся инициализация,
дописанная перед `spawn_all`.

**Собран и запущен — разные типы.** [`Iwdg::new`] отдаёт
[`Disarmed`]-сторож (регистры заполнены, счётчик стоит), [`Iwdg::arm`]
превращает его в [`Armed`], и только у второго реализован
[`watchdog::HardwareWatchdog`]. Разделить два момента было необходимо (см.
выше), а разделив, легко забыть второй — вот его и не забыть: блок
`watchdog:` требует тип с этим трейтом, то есть невзведённый сторож туда
просто не подставится. Раньше эту дыру закрывал конструктор, взводивший
железо сразу, — ценой того, что момент запуска не выбирался вовсе.

**Таймаут — параметр типа, а не аргумент конструктора.**
`BoardWatchdog = Iwdg<IWDG, HW_TIMEOUT_US, Armed>`: той же цифрой
заряжается железо и объявляется `HardwareWatchdog::HARDWARE_TIMEOUT`, по которой
`supervisor_graph!` проверяет на компиляции, что `check_every` короче
аппаратного таймаута. Возьми конструктор таймаут аргументом — объявленный
бюджет и взведённое железо стали бы двумя разными числами, и проверка
перестала бы что-либо значить (об этом прямо сказано в документации самой
константы). Побочно: выход цифры за диапазон, который IWDG умеет
отсчитать, стал ошибкой сборки вместо паники при старте.

**Узел объявлен наблюдаемым (`observe`), а не сторожевым**, и это выбор
шаблона, а не библиотеки: просрочка такого узла ДОКЛАДЫВАЕТСЯ (в лог,
через наблюдателя графа) и не превращается в аппаратный сброс. Иначе
сырой шаблон раздавал бы проект, который перезагружается сам, стоит
добавить в узел работу длиннее его таймаута, — а на плате без пробника
это выглядит как неисправное железо. Уберёте слово `observe` — узел
получит настоящую аппаратную подстраховку; ровно тогда и перечитайте оба
соотношения таймаутов в [`Iwdg::arm`].

Что при этом работает уже сейчас: железо ВЗВЕДЕНО и кормится тикером
графа. То есть исполнитель, вставший целиком (дедлок, вечная критическая
секция, зацикленное прерывание), сбрасывает плату независимо от того,
наблюдаемый узел или нет — кормить перестаёт сам тикер.
{%- else %}
Проект сгенерирован без графа задач, поэтому сторож здесь — готовый к
употреблению тип и ничего больше: `Board` его не строит и наружу не
отдаёт. Так и задумано — аппаратный сторож, которого некому кормить, это
гарантированный цикл перезагрузок, а мультиплексор кормлений живёт в
графе (`supervisor`). Собирать объект руками можно, но тогда кормить его
(`HardwareWatchdog::feed`) — тоже ваша забота.

```ignore
supervisor_graph! {
    // Сторожа в этом проекте `Board` не строит (поле есть только при
    // `graph = yes`), поэтому здесь — форма без инициализатора: объект
    // кладут в `__supervisor_watchdog.put(..)` перед `spawn_all`. Добавите
    // графу `boot: board: bsp::Board;` и полю место в `Board` — пишите
    // `= board.watchdog.arm()` прямо здесь, и забыть подключение станет
    // нельзя: сейчас пропущенный `put` — не ошибка сборки, а паника на
    // плате при первом опросе узла.
    //
    // Второй параметр типа — аппаратный таймаут в микросекундах. Он же
    // уходит в `HardwareWatchdog::HARDWARE_TIMEOUT`, по которой макрос
    // проверяет на компиляции, что `check_every` короче. Третий — состояние:
    // трейт реализован только у `Armed`, то есть у того, что вернул `arm()`.
    watchdog: bsp::wdg::Iwdg<peripherals::{{watchdog_peripheral}}, 10_000_000, bsp::wdg::Armed>,
        check_every: Duration::from_millis(100);

    // Таймаут узла обязан покрывать самый длинный законный промежуток
    // между кормлениями, а это не период работы узла, а потолок
    // backoff'а: слот сторожа регистрируется один раз и переживает
    // перезапуски.
    node APP, deps: [], restart: RestartPolicy::OnFailure, backoff: backoff(),
        watchdog: Duration::from_secs(7),
        task: app_worker;
}
```
{%- endif %}

Тип параметризован блоком, таймаутом и состоянием, а не зашит. Блок на
большинстве STM32 зовётся `IWDG`, на H7 — `IWDG1`, а на двухъядерных H7 ещё
и `IWDG2` (у ядра CM4); имя подставляется при генерации из метаданных чипа —
угадывать его по имени чипа нельзя, см. таблицу `WATCHDOG` в
`chip-select.rhai`. Таймаут — второй параметр (`const TIMEOUT_US: u32`), и
он не аргумент конструктора именно затем, чтобы взведённое железо и
объявленный `HARDWARE_TIMEOUT` были одним числом. Третий — [`Disarmed`] или
[`Armed`]; на размер объекта он не влияет (`PhantomData`), а нужен затем,
чтобы «сторож есть, но не запущен» не проходило дальше границы типа.
