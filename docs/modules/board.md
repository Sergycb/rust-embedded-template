Объекты платы: `Board` собирает их из чипа и отдаёт приложению.

Границу `bsp` → `app` пересекают только они — рычаги платы
(docs/architecture.md, «`Board` отдаёт рычаги платы, а не периферию и не
протоколы»).

Плата generic по `ports::Cpu` и о чипе не знает: ни `embassy-stm32`, ни
раскладки памяти. `Board::new(cpu)` раскладывает готовый чип по полям, а
интерфейсы над драйверами (USB-устройство, сетевой стек) собирает сам:

- `cpu_info` — сведения о чипе (`cpu::CpuInfo`);
- `flash`, `ext_flash_bus` — `Copy`-ручки чипа: разделы обновления и настройки
  строит `app` (`app::storage::ota`/`settings`);
- поля транспортов — по одному на `links` (`uart1`, `can1`, `usb1`, …): у UART
  и CAN это типы `cpu`, у USB — `bsp::usb::<транспорт>::Usb<C::<тип>>`;
- `ethernet` — `bsp::ethernet::Net` (стек и его фоновая работа);
- `system` — `cpu::system::System`;
- `watchdog` — заряженный, но не запущенный сторож `cpu::wdg`.

`Debug` печатает только `cpu_info`: у драйверов чипа `Debug` есть не у всех.
