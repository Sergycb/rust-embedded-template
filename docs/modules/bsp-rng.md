Аппаратный генератор случайных чисел (`RNG`) — затравка сетевого стека{% if net_services contains "ssh" %} и
случайность для SSH{% endif %}. Заводится только с сетевым транспортом (`tcp` или
`udp`): без сети потребителя у него в шаблоне нет, а ради неиспользуемого
блока не стоит ни клок в конфиге HAL, ни прерывание, ни модуль.

Блок приходит группой `rng` из `resources.rs` (`r.rng.rng`), и генератор наружу
из `bsp` не выходит: `Board::new` зовёт `bsp::rng::seed`, который берёт у него
одно слово затравкой сетевого стека (`bsp::net`)
{%- if net_services contains "ssh" %}
и оставляет генератор бэкендом `getrandom` (тот же модуль): блок включён всё
время работы.
{%- else %}
и дропает: блок включён только на время сборки. Нужна случайность для
криптографии — выберите при генерации службу `ssh`: с ней генератор остаётся
бэкендом `getrandom` (`bsp::rng`), и тот же путь годится любому крейту.
{%- endif %} Слово блок вырабатывает за десятки тактов своего клока, так что
блокирующий вызов исполнитель не задерживает.

## Случайность для криптографии: `getrandom`

Свой код и крипто-крейты берут случайные байты через `getrandom` 0.4 — других
путей к генератору нет, он лежит в `static` модуля `bsp::rng`:

- крейт зовёт `getrandom` сам (`sunset`) — ничего делать не нужно;
- крейт принимает генератор параметром (`ml-kem` 0.3, `x25519-dalek` 3,
  `p256` 0.14 — все на `rand_core` 0.10) — дайте ему
  `rand_core::UnwrapErr(getrandom::SysRng)`: фича `sys_rng` у `getrandom`;
- свой буфер — `getrandom::fill(&mut buf)`.

У `target_os = "none"` своего источника у `getrandom` нет. Бэкенд выбирает
`--cfg getrandom_backend="custom"` в `crates-cross/.cargo/config.toml`, а
реализует его символ `__getrandom_v03_custom` в `bsp::rng` — байты выдаются
кусками по 32 под критической секцией, чтобы длинный запрос не держал
прерывания выключенными. На хосте (`cargo xtask test host`) флага нет, и
тесты `domain` берут системный источник. Крейтам на `rand_core` 0.6/0.9
`getrandom::SysRng` не подходит, а `bsp::rng::Rng` их трейты реализует, но
занят бэкендом — понадобится обёртка над `getrandom::fill`.
{%- endif %}

Это слово — затравка стека `embassy-net` (порты, номера последовательностей
TCP): с ней они разные после каждого сброса, а не повторяются, как было бы с
затравкой из заводского номера (`seed_from_uid`, её берут чипы
без RNG).

Прерывание блока — `{{rng_irq}}`{% if rng_irq != "RNG" %}, общее с соседним блоком: драйверу
того блока нужен тот же вектор, и обработчики обоих тогда объявляются в
одном `bind_interrupts!` (в `bsp/src/rng.rs`) — второй `bind_interrupts!` с
тем же именем линкер отвергнет дублем символа{% else %}; он ни с кем не делится{% endif %}.

## Клок

Блоку нужен свой клок, и у каждой линии он свой: 48 мегагерц с выхода Q
основного PLL (F2/F4/F7), HSI48 через мультиплексор (L0, G4, H5, H7, L4,
L5, U0, U5, WB), `RNGSEL` (G0, WL, WBA). Шаблон даёт его в конфиге HAL
(`config()` в `bsp/src/board.rs`) — {% if rng_clock == "pll48" %}у этого чипа
включён PLL: HSI 16 мегагерц / 8 × 96 = 192 мегагерц на VCO, / 4 = 48 мегагерц на Q, ядро
остаётся на HSI{% elsif rng_clock == "default" %}у этого чипа ничего добавлять не
нужно: ноль мультиплексора — HSI48, а его `embassy-stm32` включает сам{% else %}у
этого чипа мультиплексор `{{rng_clock}}` переключён на `{{rng_source}}`: ноль
у него — клок, которого нет{% endif %}.

Меняете тактирование платы — сохраните клок RNG, и не ниже частоты шины
AHB, делённой на 16: медленнее блок считает клок сломанным и не выдаёт
слов{% if rng_clock == "rngsel" and rng_source == "SYS" %}. Выше 48 мегагерц его клок подниматься не должен —
источник здесь `SYS`, поднимете ядро выше — переключите `RNGSEL` или
поделите (`RNGDIV`){% elsif rng_clock == "clk48sel" and rng_source == "MSI" %}. Источник здесь — MSI на 4 мегагерцах: поднимете ядро выше
64 мегагерц — поднимите и MSI (или переключите `CLK48SEL` на PLL Q){% endif %}. Без клока `Rng::new`
{% if rng_clock == "rngsel" %}паникует на старте с именем клока, которого нет{% else %}{% if rng_clock == "default" %}у H5, H7, U5 и WB
паникует на старте с именем клока, которого нет, а у G4, L4 и L5 {% endif %}не паникует, а
виснет в ожидании слова: у RNG первой версии (F2/F4/F7, L0, L4) первое слово
отбрасывается уже в `Rng::new`, у остальных — на первом слове затравки; то и
другое — в `Board::new` (`bsp::rng::seed`). Строка `bsp: board initialized` в логе есть,
`app: …` со сведениями о чипе — нет{% endif %}. Какой источник у какой линии — таблица
`chip-data/rng.rhai` шаблона и `rng_clock` в его генераторе.
